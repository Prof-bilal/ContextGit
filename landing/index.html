Pre-releaseVersion control for LLM conversations

Branch the conversation. Merge what you learned.

ContextGit gives every LLM chat commits, branches, diffs and merges. A dead end costs you one branch, not the whole context window.

Watch a merge resolve →
pip install contextgit

The core library is in development. The install command is the planned package name.

02The problem

A chat is one line. Real thinking is a tree.

You explore, backtrack, compare and decide. Every chat app flattens that into a single scroll, and the cost shows up around message 30.

Where it hurts

  • Agentic coding. One wrong turn poisons the next fifty tool calls.
  • Research. Two hypotheses share one context and bleed into each other.
  • Prompt work. You cannot A/B a change without losing your place.

38 The context is 94% full. Your options are starting over or pasting a lossy summary. export the branch as a plain prompt, or merge the work into one compact commit.

03Workflow

Five verbs you already know.

Commit, branch, diff, merge, roll back. The CLI mirrors git, so the first session needs no manual.

A commit stores only the messages added since its parent, plus model, token count and author. Its id is a SHA-256 of that content, so history cannot change under you.

$ contextgit commit -m "Spec the limit"
[main 7be04d8] Spec the limit
 2 messages, 640 tokens, parent a3f9c21

Fork from any commit. The new branch starts with exactly the context at that point, with no leftover tangents.

$ contextgit branch redis-bucket 1d6c9a0
$ contextgit checkout redis-bucket
Switched to branch 'redis-bucket' at 1d6c9a0
 5 messages, 1,440 tokens in context

Compare two branches from their common ancestor on three levels: the messages, the meaning, and the token cost.

$ contextgit diff main redis-bucket
common ancestor  1d6c9a0

messages   main +2   redis-bucket +8
tokens     main +476 redis-bucket +3,192

semantic (redis-bucket)
  + decision  Token bucket in Redis, one Lua call per request
  + fact      Clock skew tolerated up to 50 ms
  - open      Where do counters live?  (answered)

Conversations do not merge line by line. ContextGit extracts what the branch learned and proposes a summary for you to approve.

$ contextgit merge redis-bucket
common ancestor  1d6c9a0
extracting decisions, facts, dead ends, open questions
1 conflict  logging policy (main vs redis-bucket)

Preview written. Resolve with --keep source|target,
or edit the summary. Nothing is applied until you approve.

Check out any earlier commit and keep going from there. Later commits stay put, so rolling back never destroys work.

$ contextgit checkout 7be04d8
HEAD at 7be04d8 "Spec the limit"
Later commits are untouched. Nothing was deleted.
$ contextgit branch spec-v2
$ contextgit checkout spec-v2

Illustrative output. Command names and flags may change before release.

04Merge engine

The hard part: merging meaning, not lines.

A branch is not a patch. ContextGit pulls out decisions, facts, dead ends and open questions, flags contradictions, and never resolves a conflict without you.

The algorithm

  1. 1Find the common ancestor.
  2. 2Collect source commits since the ancestor.
  3. 3Extract decisions, facts, dead ends and open questions.
  4. 4Detect conflicts against the target branch.
  5. 5Write a compact summary and show a preview.
  6. 6On approval, create a merge commit with two parents.

Prompts are versioned text files. Output is structured JSON, validated before it reaches the preview.

Merge redis-bucket into main

ancestor 1d6c9a0 · 2 source commits

decisions

  • Token bucket in Redis, one Lua call per request.
  • Refill rate comes from the key's plan, read once a minute.

facts

  • Clock skew across regions is tolerated up to 50 ms.
  • The Lua script is atomic per key.

dead ends

  • Sliding window log: memory grows with traffic.

open

  • Fail open or fail closed when Redis is unreachable?

05Interface

Three panels, one conversation tree.

The web UI puts the graph, the chat and an inspector on one screen. Click a commit and the chat becomes that moment.

Branch from any message
Fork at the exact message where the conversation went somewhere new.
Compare mode
Send one prompt to two branches and read the answers side by side.
Cherry-pick
Bring a single commit from one branch onto another.
Tag a commit
Label a known-good state and return to it in one click.
Token budget bar
See what a branch costs before you send the next message.
Export as plain prompt
Take any branch's context into any other tool.

Built to stay usable at 500 commits by collapsing linear chains. The graph is fully keyboard navigable, and branches carry text labels, never color alone.

07Status

      
Merge quality is measured, not assumed.

      
Before and after every merge, a fixed set of probe questions checks what the summary kept. A lost fact becomes a failing eval.

08Questions

      
Before you try it.

    


    

      

        Isn't this just summarizing my chat?
        
A summary replaces history. ContextGit keeps history as immutable commits and only summarizes at merge time, with a preview, a conflict check and the full branch still intact.

      

      

        Is a merge lossless?
        
No. A merge is a compact summary of decisions, facts, dead ends and open questions. That is why the original branch is never deleted, and why merge quality is tracked with probe questions.

      

      

        Where does my data go?
        
Commits live in a local SQLite file. The only network traffic is the calls you make to your chosen LLM provider.

      

      

        Which models does it work with?
        
Any model with an adapter. Every LLM call goes through one provider interface, so supporting a new provider means writing one new file. Phase 1 ships a fake provider for tests and one real adapter.

      

      

        Can I use it with the chat app I already have?
        
Not yet. A plugin API for other chat apps is on the parking lot, and any branch can already be exported as a plain prompt.

      

      

        Does it support teams?
        
Not for now. Multi-user auth, cloud sync and real-time collaboration are out of scope until the single-user core is solid.
